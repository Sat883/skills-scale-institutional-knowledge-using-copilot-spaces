# Project Kickoff Checklist

Use this checklist to ensure a smooth project start with all stakeholders aligned and essential artifacts in place.

## Pre-Kickoff Preparation

- [ ] **Project Charter/One-pager created** - Includes problem statement, objectives, success metrics, stakeholders, timeline, and team roles
- [ ] **Stakeholder list finalized** - All key stakeholders identified with their roles and contact information
- [ ] **Team roles assigned** - All core team members identified (PM, PdM, Scrum Master, Developers, QA, UX/UI, DevOps, BA as applicable)
- [ ] **Communication plan drafted** - Cadence for standups, syncs, stakeholder updates, and escalation paths defined
- [ ] **Initial risk assessment completed** - Key risks, dependencies, and mitigation strategies identified

## Project Artifacts Setup

- [ ] **Repository/project workspace created** - GitHub repo or project board established
- [ ] **Documentation structure initialized** - docs/ folder with essential templates and README
- [ ] **Project Charter added to repository** - Placed in docs/ or .copilot/ for easy reference
- [ ] **Communication channels established** - Slack/Teams channels, email groups, or meeting invites sent
- [ ] **Access and permissions granted** - All team members have necessary access to tools, repos, and systems

## Kickoff Meeting Preparation

- [ ] **Agenda prepared** - Clear objectives and time allocation for kickoff meeting
- [ ] **Presentations/materials ready** - Project overview, timeline, roles, and success metrics prepared
- [ ] **Logistics confirmed** - Meeting time, location/link, duration, and participants confirmed
- [ ] **Pre-read materials shared** - Project Charter and key documents sent to participants 24+ hours in advance

## During Kickoff Meeting

- [ ] **Introductions completed** - All team members and stakeholders introduced with roles clarified
- [ ] **Project vision and objectives presented** - Problem statement, goals, and success metrics shared
- [ ] **Scope and timeline reviewed** - High-level milestones, deliverables, and key dates discussed
- [ ] **Roles and responsibilities clarified** - Each role's ownership and interaction points explained (refer to Role-Responsibility Matrix)
- [ ] **Communication cadence confirmed** - Standups, syncs, status updates, and reporting rhythm agreed upon
- [ ] **Dependencies and risks discussed** - Key risks, blockers, and cross-team dependencies surfaced
- [ ] **Working agreements established** - Team norms, decision-making processes, and escalation paths defined
- [ ] **Q&A session held** - Team questions addressed and concerns resolved
- [ ] **Next steps identified** - Immediate action items with owners and due dates

## Post-Kickoff Actions

- [ ] **Meeting notes distributed** - Kickoff summary, decisions, and action items shared with all participants
- [ ] **Action items tracked** - Kickoff action items added to project board with owners and deadlines
- [ ] **Project Charter updated** - Any decisions or changes from kickoff incorporated into Charter
- [ ] **Onboarding initiated** - New team members directed to README and key documentation
- [ ] **First sprint/iteration planned** - Initial backlog grooming and sprint planning scheduled
- [ ] **Baseline metrics established** - Initial metrics captured for tracking progress and success

## Quality Assurance Checkpoints

- [ ] **Acceptance criteria clarity confirmed** - Team understands Definition of Done and quality standards
- [ ] **Testing strategy aligned** - QA approach, test environments, and automation strategy discussed
- [ ] **Design review process established** - UX/UI review gates and feedback loops confirmed
- [ ] **Code review and deployment processes confirmed** - Development workflow, CI/CD, and release process agreed upon

## Communication and Artifact Maintenance

- [ ] **Documentation ownership assigned** - Clear owners for maintaining Project Charter, roadmap, and key docs
- [ ] **Update frequency agreed** - How often artifacts (Charter, risk register, retros) will be reviewed and updated
- [ ] **Stakeholder reporting cadence set** - Monthly or milestone-based updates scheduled
- [ ] **Retrospective schedule established** - Sprint, milestone, or release retro cadence defined

---

## Tips for Success

- **Keep it concise**: Kickoff meetings should be 60-90 minutes max; use pre-reads for detailed information
- **Encourage questions**: Create psychological safety for team members to ask questions and raise concerns
- **Document decisions**: Capture key decisions and rationale in meeting notes for future reference
- **Follow up quickly**: Send notes and action items within 24 hours of kickoff to maintain momentum
- **Revisit regularly**: Reference this checklist at project milestones to ensure ongoing alignment
